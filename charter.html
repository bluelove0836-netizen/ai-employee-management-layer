The Claude Code delegation charter: template + how to write one

A prompt tells a Claude Code agent what to do once. A charter tells it what a role is allowed to be. That's the difference between a task and an employee — and it's what lets an agent run autonomously without drifting or overstepping.

The template

A charter is one short markdown file that travels with the agent (keep it next to the agent in .claude/agents/ or a charters/ folder):

# Charter: [role-name]

Mandate:      [the one job, measurable — e.g. "Publish 1 post/day to the blog queue"]
Authority:    [what it MAY do — files it can edit, endpoints it can call]
Boundaries:   [what it must NEVER do — "never touches billing", "never publishes without a draft on disk"]
Definition of done:
              [a real artifact, not a green log — e.g. "a live public URL is returned
               AND written to /published/YYYY-MM-DD.json"]
Escalate to human when:
              - auth / login is required
              - a payment or new account is involved
              - anything irreversible
Report format:
              [one line per run: what shipped, the verified number (or "unverified"), blockers]

Why each field matters

Mandate keeps the agent from scope-creeping into other roles. Authority lets it act without asking permission for things clearly inside its lane — the #1 reason autonomous agents feel slow is an unclear authority line. Boundaries are the fence it stops at. Definition of done must be an external artifact (a live URL), never "the script exited 0" — exit codes lie. Escalate-to-human is the short list of things only a person may do; the agent files these as blockers instead of improvising a dangerous workaround.

The one rule that makes it work

The agent runs free inside the fence and stops at the fence — because the fence is written down, not inferred. Agents behave measurably better when both the freedom and the boundary are explicit.
