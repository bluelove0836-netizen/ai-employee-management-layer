How to manage Claude Code agents so they don't fail quietly

The agents are the easy part now — free packs of 100+ exist. What actually breaks a multi-agent setup is management. Here are the 5 rules from a real solo operation running several pipelines on Claude Code every day.

My scheduler logged success for six days while publishing nothing. That week is why this guide exists.

The reframe: agents are commodities, governance isn't

If your automation is failing, it's almost never a missing code-reviewer.md. It's failing for boring operational reasons: an agent reported success it didn't earn, two agents fought over the same file, one invented a number you almost shipped, a job died silently for days. None of that is an agent problem — it's a governance problem.

Rule 1 — Delegation is a written contract, not a prompt

A prompt says what to do once. A charter says what a role is allowed to be. It travels with the agent as plain markdown:

# Charter: publish-lead
Mandate:    Publish 1 post/day to the blog queue.
Authority:  May edit drafts in /drafts. May call the publish endpoint.
Boundaries: Never touches billing. Never publishes without a draft on disk.
Definition of done:
            A live public URL is returned AND written to /published/YYYY-MM-DD.json
Escalate to human when: auth required, payment/new account involved, queue empty.

The agent runs free inside the fence and stops at the fence — because the fence is written down, not inferred.

Rule 2 — Trust artifacts, not exit codes

The most expensive failure in unattended automation: the log says success, reality says nothing happened. Verify live external state every run:

curl -s https://your-site.com/ | grep -q "$(date +%Y-%m-%d)" \
  && echo ALIVE || echo "NO ARTIFACT TODAY — pipeline is DOWN"

A pipeline is alive only if today's public artifact actually exists. Exit 0 lies; artifacts don't.

Rule 3 — Facts only

No agent may state a number without a live source; otherwise it says unverified. Agents fabricate to be helpful — which is worse, because it reads as confident. This one rule is the difference between a dashboard you trust and one that flatters you.

Rule 4 — One lead per lane

One owning agent per pipeline. A do-everything agent drifts within a week; a narrow one builds deep context and its failures stay contained. Twelve narrow agents beat one wide one — like job descriptions beat "just handle stuff."

Rule 5 — Memory is infrastructure

Keep durable memory as one fact per file plus an index the agent reads each session. Write the why, not just the what. Delete wrong memories aggressively. Month two should feel like working with someone who was there in month one.
