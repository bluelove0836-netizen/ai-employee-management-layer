5 checks before you trust a Claude Code agent unattended

A working demo is not a working system. When you leave a Claude Code agent running unattended, it almost never fails loudly — it fails quietly. These five checks catch the quiet failures.

1. Does the agent verify the artifact, not the exit code?

The most expensive failure: the log says success, reality says nothing happened. A scheduled job can log success for days while an expired session silently publishes nothing. The agent must check live external state:

curl -s https://your-site.com/ | grep -q "$(date +%Y-%m-%d)" \
  && echo ALIVE || echo "NO ARTIFACT TODAY"

A job is done only if today's public artifact actually exists. Exit 0 lies.

2. Is the session valid right now?

Not "did it work yesterday." One cheap authenticated call each run. Auth for stats often dies before auth for publishing, so a "no data" day can secretly be a "monitoring is broken" day.

3. Can it state a number it can't source?

Give the agent one rule: no number without a live source, otherwise say unverified. Agents fabricate to be helpful — which is worse, because it reads as confident. This catches the number that quietly ends up in a report you almost sent.

4. Is there a written boundary it can't cross?

Payments, new accounts, legal terms, publishing under your name — the agent must escalate these as blockers, never improvise around them. If the boundary isn't written down in a charter, the agent will eventually guess.

5. Will a missed run be visible?

If the scheduler silently unloads (OS update, migration), nothing runs and nothing notices. Verify the job is still loaded (launchctl list / crontab -l) and that a report line landed for every scheduled run.
